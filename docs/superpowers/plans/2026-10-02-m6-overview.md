### 2.3 출처 처리기 계약 (`reg.core.ingest.contract`)

```python
@dataclass
class PreparedVersion:
    work_id: str
    work_kind: str                 # INTERNAL_REG | 법률 | 대통령령 | … | 행정규칙 종류
    title: str
    institution_id: int | None
    source_document_id: int
    doc: ParsedDoc
    effective: Effective
    external_ids: dict
    posted_on: date | None = None

@dataclass
class SourceHandler:
    topic: str                      # outbox 주제 (기존 이름 유지: regulation.source_fetched / regulation.law_fetched)
    group_field: str                # 묶음 기준 payload 필드 (seq / law_id)
    prepare: Callable[[Connection, BlobStore, dict, date, Converter | None], PreparedVersion | None]
```

- `reg.core.ingest.registry`: `register(h)`, `handlers() -> dict[str, SourceHandler]`, `clear()`(테스트용)
- 출처 패키지는 `HANDLERS: list[SourceHandler]`와 `MIGRATIONS: MigrationLocation | None`을 `__init__.py`에 둔다.
- `reg.wiring.register_sources()`가 이를 등록한다. 테스트 conftest와 CLI가 이것을 호출한다.

### 2.4 마이그레이션 계약 (`reg.platform.db.migrate`)

```python
@dataclass(frozen=True)
class MigrationLocation:
    name: str           # core | alio | lawgo
    path: Path          # alembic 스크립트 폴더
    schema: str         # version table 스키마
    version_table: str  # alembic_version | alembic_version_alio | alembic_version (law 스키마)

def upgrade(migrator_dsn: str, locations: list[MigrationLocation]) -> None   # 순서대로 head까지
```

- 실행 순서: core → alio → lawgo (`reg.wiring.migration_locations()`).
- **core 이력(0001~0008)은 M6-0만 고친다.** 트랙이 core·ops 테이블에 필요한 변경은 0008에 미리 넣었다(§2.5). 트랙에서 더 필요하면 자기 모듈 이력에 넣는다.

### 2.5 0008에 선반영한 스키마 (트랙이 바로 쓴다)

| 대상 | 변경 | 쓰는 트랙 |

### 2.6 Airflow 진입점 계약 (`tasks.py`)

모든 함수는 다음 규칙을 따른다.
- 인자 없이 또는 단순 인자(문자열, 날짜 문자열)로 호출된다.
- 스스로 설정을 읽고 DB에 연결한다.
- `ops.pipeline_run`에 기록하고(`reg.platform.runs.task_run` 컨텍스트), **JSON 직렬화 가능한 dict**를 돌려준다.
- 실패는 예외로 알린다(Airflow 재시도 대상).

| 모듈 | 함수 | 만드는 곳 |
|---|---|---|
| `reg.sources.alio.tasks` | `active_institutions() -> list[str]`, `collect_institution(code: str) -> dict`, `reconcile(results: list[dict]) -> dict` | M6-0 (`reconcile`은 빈 구현 대신 M6-2가 추가) |
| `reg.sources.lawgo.tasks` | `sync_daily(day: str \| None = None) -> dict`, `sync_full() -> dict`, `link() -> dict`, `promote() -> dict` | M6-1 |
| `reg.core.ingest.tasks` | `process_all() -> dict`, `quality_summary() -> dict` | M6-0 |
| `reg.ocr.tasks` | `run_pending(limit: int = 50) -> dict` | M6-5 |
| `reg.graph.tasks` | `sync() -> dict` | M6-0 |
| `reg.alerts.tasks` | `scan() -> dict`, `notify() -> dict` | M6-0 |
| `reg.index.tasks` | `embed_check() -> bool`, `build() -> dict`, `gate(release_id: int) -> dict`(품질 미달은 `GateFailed`, 서버 장애는 `ProviderError`), `publish(release_id: int) -> dict`, `prune() -> dict` | M6-0은 `build()`(기존 동작)만, 나머지는 M6-4 |
| `reg.ops.tasks` | `daily_summary() -> dict`, `maintenance() -> dict` | M6-3 |

- 이 표에 없는 함수를 DAG에서 부르지 않는다.
- M6-3 DAG 테스트는 DAG 파일을 import만 한다(DagBag). 아직 다른 트랙에 있는 함수는 DAG 안에서 지연 import하므로 병렬 개발 중에도 테스트가 통과한다.

### 2.8 기관 정보 저장 규칙 (사용자 요구 2026-10-02: "데이터 저장할 때 기관명도 저장 → 기관별 검색")

모든 저장 단계에서 기관을 **코드와 이름 둘 다** 남긴다. 검색은 코드·정식명·약칭 어느 것으로도 기관을 거를 수 있어야 한다.

| 저장 위치 | 저장할 것 | 담당 |
|---|---|---|
| `regulation.institution` | `code`, `name`(정식명), `aliases text[]`(약칭: 천문연, 키스트, 에트리 …, `config/sources/alio.yaml`에서) | M6-0 (0008에 `aliases` 컬럼 추가) · M6-2(yaml에 약칭 기재) |
| 조회 뷰 `regulation.v_regulation_master` | 규범문서 1행 = 기관 코드·기관명·규정명·현행 버전·시행일·상태·조항 수 | M6-0 (0008) |
| `regulation.source_document.source_meta` | `institution_code` + **`institution_name`** (수집 시점의 이름) | M6-2 (alio sync가 기록) |
| OpenSearch 청크 | `institution`(코드, 기존) + **`institution_name`**(keyword + nori text) + **`institution_aliases`**(keyword 배열). 법령·행정규칙은 `institution`=`LAW`, `institution_name`=소관부처명 | M6-4 (매핑·indexer), 법령 소관부처는 M6-1이 `regulation.work.external_ids.ministry`로 넘긴다 |
| 검색 API·질의응답 | `institution` 파라미터에 코드·정식명·약칭 모두 허용(서버가 코드로 정규화). 질의 문장의 기관명은 BM25에서 `institution_name`에도 매칭 | M6-4 (`index.service`) |
| `law.law_master` | `ministry`(소관부처명), `ministry_code` | M6-1 |
| MinerU·OCR 결과 | 원본 문서(`source_document_id`)에 묶이므로 기관은 원본에서 이어받는다 (별도 저장 없음) | — |

## 3. 공유 파일 규칙 (병렬 충돌 방지)

| 파일 | 규칙 |
|---|---|
| `reg/wiring.py` | 트랙은 자기 모듈의 줄만 추가한다(M6-5: `reg.ocr.cli`) |
| `reg/api/app.py` | 트랙은 `app.include_router(...)` 한 줄만 추가한다. 엔드포인트는 자기 라우터 파일에 둔다(M6-1: `api/law_routes.py`) |
| `apps/web/src/lib/api.ts` | 타입 추가만 (파일 끝에) |
| `infra/docker-compose.yml` | M6-3만 서비스를 추가한다. M6-5 OCR 이미지는 `infra/ocr/Dockerfile`(compose 서비스 아님, 변환기처럼 `docker run`) |
| `pyproject.toml` | 의존성 추가만 (병합 시 `uv lock` 재생성) |
| `tests/conftest.py` | 트랙은 자기 픽스처를 `tests/<모듈>/conftest.py`에 둔다 |
| `reg/core/{extract,text,parse,refs,anchor}` | **M6-6만** 고친다. M6-5는 `sources/alio/handler.py`에서 이 함수들을 호출만 한다 |
| `sources/alio/handler.py` | M6-5(OCR)만 고친다(최소 수정). M6-2는 다른 alio 파일만 고친다 |

## 4. 실서버 원칙 (트랙 공통)

- 트랙은 **실서버 서비스(21060/21061 웹·API, Airflow)를 재시작하거나 실 DB에 쓰지 않는다.** 테스트는 testcontainers로 한다.
- 외부 사이트 호출은 다음까지만 허용한다.
  - 계약 테스트용 응답 수집(소량)
  - law.go.kr: 운영 OC 키 `REG_LAWGO_OC`. 승인 대기 중이면 개발용 `test`로 응답 표본을 모은다.
- 실연결(법령 최초 적재, OCR 107건, Airflow 기동)은 통합 단계에서 메인 세션이 한다.
