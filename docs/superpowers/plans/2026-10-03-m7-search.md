# M7-S 조·항·호·목 단위 검색 (OpenSearch) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 조 덩어리 청크 색인을 provision_version 1건 = 문서 1건 색인(`reg-provisions-r{N}`)으로 바꾸고, 번호 직접 조회·조 단위로 묶은 하이브리드 검색(맞은 항·호 하이라이트)·집계·자동완성을 API·웹·질의응답에 연결한다.

**Architecture:** `reg.index`가 문서 모델(units)·매핑·빌드·게시(release/gate/prune 유지)와 조 단위로 묶는 하이브리드 검색 엔진(`reg.index.service.search`, 기존 시그니처 호환)을 가진다. 새 `reg.search`(platform·core·index만 import)가 번호 인용 파서·직접 조회·자동완성·집계를 얹는다. `reg.qa`는 `reg.search`의 묶음 결과에서 `matches`(맞은 항 경로)를 근거로 넘긴다.

**Tech Stack:** Python 3.12, OpenSearch 2.19.1(nori, knn, neural-search 하이브리드 파이프라인), psycopg 3, FastAPI, Next.js 16(app router, 서버 컴포넌트), pytest + testcontainers(`nais-opensearch:2.19.1-nori`).

**Spec:** `docs/superpowers/specs/2026-10-03-graph-search-redesign.md` §0, §2, §3, §4 (모듈 규칙: `docs/superpowers/plans/2026-10-02-m6-overview.md` §2.2)

## Global Constraints

- 색인 `reg-provisions-r{N}`, 별칭 `reg-provisions`. 문서 1개 = 조항 판본 1개(provision_version)를 그 판본(work_version)에서 본 것. 장·절은 문맥(breadcrumb)으로만.
- 모든 dated 판본을 넣는다. 벡터는 **현행 판본의 조·항·별표 조각에만**. 임베딩 입력은 4,000자에서 자르고 `ops.embedding_cache`를 쓴다.
- 긴 단위(>1,200자)는 `#n` 조각으로 나눈다(M6 창 분할 규칙).
- 분석기 `ko`(nori mixed), `ko_syn`(`ko` + synonym_graph `config/search_synonyms.txt`), 사용자 사전 `config/search_userdict.txt`.
- BM25(`text^3`, `heading^2`, `full_label`, `breadcrumb`) + knn(현행), min_max 0.4/0.6, 리랭크, 조 단위 묶음(`article_path`+`version_id`), 하위 단위·하이라이트.
- 필터: 기관(코드·이름·약칭), 종류, 단위, 기준일, 현행만. 집계: 기관별·규정별. 자동완성: 규정명.
- `reg.index`는 `reg.platform`·`reg.core`만 import. `reg.index` 공개 API(`build_release`, `service.search`, release/gate/publish/prune, tasks, cli)는 호환 유지.
- 품질: 번호 조회는 평가 세트 기대 조문이 1위, QA 인용 정확도 ≥ 0.90(결론 정확도 1.0 유지), 검색 p95 < 1.5초.
- 실서버: 전용 클러스터(`REG_GPU_OS_URL`, 192.168.0.2:8005)에만 만든다. 공유 클러스터(127.0.0.1:21067, `nais-*`)는 건드리지 않는다. 평가는 PG 읽기 전용.
- 서버 제약: 테스트는 `nice -n 15`, pytest 한 번에 하나. 전체 스위트는 끝에 한 번(`free -g` 가용 ≥ 6GB).

```python
"""조·항·호·목 단위 색인 문서 (M7 spec §2.1): provision_version 1건 = 문서 1건, 긴 단위는 #n 창."""
import re
from dataclasses import dataclass

MAX_CHARS = 1200                      # M6 창 분할 규칙과 같다 (임베딩 입력 캐시 재사용)
VECTOR_UNITS = {"article", "paragraph", "annex"}
CONTEXT_ONLY = {"chapter", "section"}
RE_ART = re.compile(r"a(\d+)(?:-(\d+))?(?:~\d+)?$")

@dataclass
class UnitDoc:
    doc: dict
    embed_text: str | None

def article_path(path: str) -> str:
    return re.split(r"[.#]", path, maxsplit=1)[0]

def numbers(path: str) -> dict:
    p = path.split("#")[0]
    if m := re.fullmatch(r"(?:annex|form)(\d+)(?:-(\d+))?(?:~\d+)?", p):
        return {"annex_no": int(m[1]), "annex_branch": int(m[2] or 0)}
    if p.startswith("supp"):
        return {}                     # 부칙 조문은 본칙 번호 조회에서 뺀다
    head, *rest = p.split(".")
    if not (m := RE_ART.fullmatch(head)):
        return {}
    out = {"article_no": int(m[1]), "article_branch": int(m[2] or 0)}
    for seg in rest:
        if m := re.fullmatch(r"p(\d+)(?:~\d+)?", seg):
            out["paragraph_no"] = int(m[1])
        elif m := re.fullmatch(r"i(\d+)(?:-(\d+))?(?:~\d+)?", seg):
            out |= {"item_no": int(m[1]), "item_branch": int(m[2] or 0)}
        elif m := re.fullmatch(r"s([가-힣])(?:~\d+)?", seg):
            out["subitem"] = m[1]
    return out
```
