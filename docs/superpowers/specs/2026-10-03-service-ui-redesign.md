# 서비스 UI 개편 설계 v2 — "우리 기관 규정을 쉽게 찾고, 다른 기관과 비교해 배운다"

- 작성 2026-10-03 · 상태: **사용자 승인(스토리보드 v2: https://claude.ai/artifact/GcAyzq4MZMBp6131Qv3Avd), 구현 진행**
- 목적(사용자 원문 요지): 각 기관의 행정원·연구자가 법령·규정을 더 편하게 찾고, **우리 기관 규정과 다른 기관의 비슷한 내용을 비교해 "저 기관은 저렇게 하는 게 효율적이구나"를 쉽게 알게** 한다. 데모가 아니라 서비스 페이지. "LLM이 만든 티"가 나지 않게.

## 1. 앱 셸

- 왼쪽 사이드바 240px(`--bg-subtle`, 1px 경계, 접기 64px 레일, 모바일 시트): 홈 · 규정 찾기 · 기관 비교 · 규정 도우미 · 법령 · 검수 / 그룹 "우리 기관"(선택한 기관 표시, 누르면 바꾸기) / 하단 "개정 알림 · 준비 중".
- 상단 바 48px: 브레드크럼, ⌘K 명령 팔레트(규정·조문 찾기, 화면 이동; cmdk) — 입력하면 규정 도우미로 넘길 수도 있다.
- **우리 기관**: 처음 방문 시 기관을 고르게 하고(건너뛰기 가능 = 전체), localStorage(try/catch)와 URL `?inst=`로 유지. 홈·규정 찾기 기본 필터·비교표 첫 열에 쓰인다. 규정 도우미의 질문 범위와는 별개.

## 2. 홈 — 우리 기관 (`/`)

- 머리: 기관명(display), 현행 규정 수·판본 수·마지막 수집 시각, 버튼 "우리 규정 전체"(보조), "규정 도우미"(주).
- **다른 기관과 다른 점**(핵심): 비교표(§4)의 항목 중 우리 기관 값이 다수 기관과 다른 것 상위 N개 — 주제, 항목, 우리 기관 값(근거 조문 링크), 다수 기관 값(기관 수), "비교" 버튼.
- **최근 바뀐 우리 규정**: 시행일, 규정명, 제정/개정, 바뀐 조문 요약(provision_change 기반, 짧게; 요약을 못 만들면 바뀐 조문 목록).
- 오른쪽 레일 300px: 주제별 우리 규정 수(누르면 기관 비교), 최근 본 조문(localStorage).
- 기관 미선택(전체) 상태: 같은 자리에 기관별 현황 표(기관, 현행 규정, 판본, 최근 개정일, 열린 검수).

## 3. 규정 찾기 (`/regulations`) · 규정 보기 (`/regulations/[...id]`)

- 찾기: 왼쪽 필터 레일 220px(검색 입력, 기관 체크 목록—우리 기관 맨 위, 주제, 종류(규정/요령·지침/기준·세칙/법령), 상태), 본문 표(규정, 기관, 주제, 시행일, 조문 수), 보기 전환 SegmentedControl "목록 | 기관별 묶기", 정렬, 페이지네이션. 머리 버튼 "찾은 규정 기관별로 비교"(→ 기관 비교, 같은 주제로).
- 보기(기존 뷰어 재구성): 머리(기관·주제 캡션, 제목, 시행 판본, 판본 비교·원문 PDF·이 규정에 묻기), 탭(본문 | 개정 이력 | 관계도 | 별표·서식), 3열 = 조문 목차 200px | 본문(최대 72ch, 15/26) | 오른쪽 레일 300px **"다른 기관의 같은 조항"**: 선택한 조(없으면 첫 조)와 의미가 비슷한 다른 기관 조항 상위 5개(기관, 규정 제N조, 핵심 값, 같음/다름 배지), "나란히 보기"(→ 기관 비교 조문 나란히). 참조 팝업·음영, 관계도, 판본 이력은 유지.

## 4. 기관 비교 (`/compare`)

- 머리: 주제(Select), 비교 기관 칩(우리 기관 고정 첫 열 + 최대 5개 추가, 기본 = 비교값이 있는 기관 중 우리 기관과 다른 곳 우선), "차이만 보기", 보기 전환 "항목 표 | 조문 나란히", 내보내기(CSV).
- **항목 표**: 행 = 주제의 비교 항목, 열 = 기관. 칸 = 짧은 값 + 근거 조문 링크. 우리 기관 값과 다른 칸은 `--warning` 면(옅은 노랑)으로. 값이 없으면 "규정 없음"(회색).
- **조문 나란히**: 한 항목을 골라 기관별 근거 조문 원문을 열로 나란히, 값 부분 강조.
- 데이터: `config/topics.yaml`(주제 정의와 비교 항목) · `regulation.work_topic`(규정 ↔ 주제, 제목 규칙 + 임베딩 유사도 분류, 규정당 최대 2개) · `regulation.compare_cell`(주제 · 항목 × 기관: 근거 조문 판본 id, 값, 정규화 값, 인용 원문, 방법·신뢰도, 추출 시각). 값 만들기: 기관별로 그 주제 규정 안에서 하이브리드 검색(OpenSearch `reg-provisions`, 기관·work 필터)으로 근거 조문 후보를 찾고, EXAONE(vLLM, 정규식 줄 형식 출력)으로 짧은 값과 인용을 뽑는다(인용이 원문에 그대로 있어야 저장). 배치 `reg topics classify`, `reg compare build [--topic] [--inst]`, 처리 DAG 이후 변경된 기관만 다시. 다수 값 = 정규화 값의 최빈값.
- 1차 비교 항목(설정): 여비·출장(증빙 제출 기한, 여비 정산 기한, 일비, 국내 숙박비 상한, 국외출장 사전 심의), 회계·재무(회계연도, 예산 이월, 지출 결의 기한, 결산 보고 기한), 계약·구매(수의계약 한도 물품·용역, 계약 심의 기준액, 검수 기한), 인사·복무(수습 기간, 유연근무 신청, 연차 이월), 연구관리(연구장비 도입 심의 기준액, 연구노트 보존 기간, 연구비 정산 기한), 보안(보안 서약, 외부 반출 승인). 항목은 설정 파일로 계속 늘린다.

## 5. 규정 도우미 — 검색과 질의응답 통합 (`/assistant`, ⌘K에서도)

- 백엔드 `POST /api/v1/chat` (SSE): 입력 `{messages[≤6턴], scope: {mode: "all"|"institutions", institutions?: [], topic?, work_ids?}, as_of?}`. 질문에 기관 이름이 있으면 그 기관으로 좁힌다(범위가 "기관 선택"이면 선택이 우선). 기존 qa 분석·하이브리드 검색·그래프 근거 확장·EXAONE 생성·검증을 재사용한다.
  - 의도: 조문 찾기형(번호·제목 → 조문 카드, 생성 없음) / 질문형(결론·설명 + 근거) / **여러 기관 비교형**(전체 범위이거나 "다른 기관도" → 기관별 값 표; `compare_cell`을 먼저 쓰고 없으면 기관별 검색 상위 조문에서 추출).
  - 모든 근거는 **원문 그대로의 인용**(Harvey식) — 인용이 원문에 없으면 버린다.
  - 이벤트: `status` · `results`(조문 카드) · `answer_delta` · `answer`(결론, 문장별 근거 번호) · `table`(기관별 비교) · `citations`(번호, 기관, 규정 제N조 항, 인용 원문, 링크) · `followups` · `done`. 실패해도 근거 카드는 보낸다.
  - `/api/v1/qa`, `/api/v1/hsearch`는 호환 유지. 대화 기록은 `ops.qa_log`에 대화 id와 함께.
- 화면: 가운데 대화(사용자 말풍선은 `--bg-hover` 면, 도우미 답변은 면 없이 본문, 인용 번호 위첨자), 기관별 비교 표, 후속 질문(보조 버튼), 아래 입력 상자(범위 버튼 "범위: 전체 기관 ▾" → 팝오버에서 전체 / 기관 선택(다중, 검색)), 오른쪽 레일 320px "근거 N"(번호·기관·조문·인용 원문 강조) + 질문 범위. 최근 대화(localStorage)는 접힌 목록.
- `/search`, `/qa`는 `/assistant`로 이동(redirect, 쿼리 보존).

## 6. 검수 (`/review`)

- 백엔드: `GET /api/v1/review-tasks` 보강 — 기관(코드·이름), 규정 제목, 판본 시행일, 위치 라벨(제13조 제2항), 원문 발췌, **문제**(종류별 한국어 문장), **해야 할 일**(종류별 안내), 소관부서(ALIO `jidtDptm`), 담당, 상태, 생성일; 필터(기관·종류·상태·담당·검색), 페이지네이션, 집계(열림·내 담당·담당 없음·법령 적재 대기). 처리: `POST …/{id}/assign {assignee}`, `…/resolve {decision, note}`, `…/dismiss {reason}`, `…/hold`. 담당자 이름은 로그인 전까지 사용자가 입력한 이름(localStorage).
- 법령 이름 참조 미해석(law.go.kr 적재 대기)은 "법령 적재 대기"로 묶어 기본 목록에서 뺀다.
- 화면: 머리, 숫자 줄(카드 아님), 툴바(상태 Segmented, 기관·종류·담당 필터), 표(선택, 기관, 규정·위치, 문제, 해야 할 일, 담당, 상태), 행 펼침(원문 발췌·원문 PDF·연결 지정·문제 없음·보류). 기존 깨진 레이아웃 전부 정리.
