# PRD — NST 규정·법령 인텔리전스 플랫폼

- 작성일: 2026-10-01
- 상태: 초안, 검토 대기
- 기술 설계: [설계 스펙](superpowers/specs/2026-10-01-regulation-platform-design.md)

---

## 1. 한 줄 요약

국가과학기술연구회와 출연연의 내부규정, 그리고 관련 법령을 **조문 단위로 구조화해서 버전과 함께 관리**한다. 그 위에서 세 가지를 제공한다.

- law.go.kr 같은 규정 뷰어
- **소속 기관 규정의 원문 근거를 먼저 보여주는 AI 질의응답**
- **법령·규정이 개정되면 영향받는 조항의 담당자에게 자동으로 가는 알림**

## 2. 문제

1. **찾기 어렵다.** 기관별 규정이 ALIO에 HWP·PDF 파일로 흩어져 있다. 연구자가 "출장 후 며칠 안에 정산해야 하지?" 같은 질문의 답을 찾으려면 파일을 열어 일일이 읽어야 한다.
2. **기관마다 다르다.** 같은 질문이라도 기관에 따라 답이 다르다. 실제 확인한 예는 다음과 같다.
   - 천문연 여비규정 제27조: 증빙 제출 **7일 이내**
   - NST 여비규정 제9조의2: 국내출장 정산 신청 **10일 이내**

   일반적인 답이나 다른 기관의 답은 틀린 답이 된다.
3. **현행인지 알기 어렵다.** 개정 이력, 시행일, 부칙의 경과조치가 파일 안에 묻혀 있다. 그래서 지금 적용되는 조문이 무엇인지 판단하기 어렵다.
4. **개정 영향을 놓친다.** 상위 법령이나 모규정이 바뀌어도, 그것을 참조하는 내부규정 조항을 찾아 정비하는 일이 사람의 기억에 의존한다.

## 3. 사용자

| 사용자 | 하는 일 | 핵심 요구 |
|---|---|---|
| 연구자·직원 | 출장, 연구비, 인사 등 규정 질문 | 우리 기관 기준의 정확한 근거, 짧은 설명 |
| 행정담당자 | 규정 해석과 안내, 민원 응대 | 원문, 버전, 신구 비교, 관련 규정 묶음 |
| 규정 담당자 (소관부서) | 규정 정비 | 개정 영향 알림, 검토 기록 |
| 검수자 | 자동 추출 결과 확인 | 원문 대조 화면, 빠른 승인·수정 |
| 기관·플랫폼 관리자 | 대상 기관, 담당자, 품질 관리 | 수집·게시 현황, 품질 지표 |

## 4. 핵심 시나리오

**S1. 근거 기반 질의**

> "천문연 소속인데 출장 다녀온 지 10일 지났고 지출결의를 아직 안 했어요. 문제가 없을까요?"

시스템은 다음 순서로 답한다.

1. 기관을 천문연으로 확정한다.
2. 여비규정 제27조①(7일 이내 증빙 제출)과 제4조의2(정산)의 원문을 **먼저** 보여준다.
3. "증빙 제출 기한(7일)이 지났습니다"라고 설명한다.
4. 확인 필요 사항을 덧붙인다. 규정에는 "지출결의"라는 용어가 없으니 내부 절차와 같은지 확인해야 한다.
5. 문의처로 회계담당부서를 안내한다.

기관을 알 수 없으면 답하기 전에 되묻는다.

**S2. 과거 시점 질의**

> "작년 3월 출장 때 기준으로는?"

그 시점에 시행 중이던 버전으로 답한다. 그 뒤에 개정이 있었다면 개정 사실과 경과조치를 함께 알려준다.

**S3. 규정 열람과 원문 대조**

뷰어에서 조문을 누르면, 원본 PDF(HWP는 PDF로 변환한 보기용 사본)가 해당 위치로 이동하고 그 문구를 강조한다. 원본 파일도 내려받을 수 있다.

**S4. 개정 알림**

어떤 시행령이 개정되면, 그 조문을 근거로 삼는 내부규정 조항의 담당자에게 다음 내용이 담긴 알림이 간다.

- 신구 비교
- 영향 유형과 심각도
- 검토 포인트

담당자가 "조치 필요 / 불필요"를 기록하고, 이후 내부규정이 개정되면 자동으로 "완료"로 연결된다.

## 5. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | ALIO에서 대상 기관의 내부규정과 **개정 이력 파일 전체**를 매일 수집한다. | P0 |
| FR-02 | law.go.kr Open API에서 관련 법령의 현행 본문, 조문시행일, 연혁을 수집한다. | P0 |
| FR-03 | HWP / HWPX / PDF에서 텍스트를 추출하고, 보기용 PDF를 만든다. | P0 |
| FR-04 | 편·장·절·조·항·호·목, 별표·별지, 부칙으로 구조화한다. 개정 주석도 분리한다. | P0 |
| FR-05 | 조문 안의 참조를 추출하고 대상을 해석한다. 관계 유형은 6가지다. (근거 / 위임 / 시행 / 준용 / 예외 / 단순참조) | P0 |
| FR-06 | 공포·개정·시행일을 구분하고, 조항별 시행일을 반영한다. 불명확하거나 충돌하면 **검수 큐**로 보낸다. | P0 |
| FR-07 | 모든 버전을 보존한다. 기준일 조회와 조항 단위 신구 비교를 제공한다. | P0 |
| FR-08 | 규정 뷰어: 목차, 본문, 참조 링크, 관계 패널, **원문 대조 보기**, 원본 다운로드 | P0 |
| FR-09 | 키워드 검색과 하이브리드(의미) 검색. 기관, 문서 종류, 기준일로 거른다. | P0 |
| FR-10 | 질의응답 | P0 |
|  | · 기관을 확정하고, 정할 수 없으면 되묻는다. | |
|  | · 근거 원문을 먼저 보여준다. | |
|  | · 결론은 미충족 / 충족 / 조건부 / 판단불가 중 하나다. | |
|  | · 인용·숫자·일관성 검증을 통과한 설명만 보여준다. | |
| FR-11 | 관련 규정이 없으면 "찾지 못함"으로 답하고, 판단이 불확실하면 "판단불가"로 답한다. 판단이 필요한 사안은 문의처를 안내한다. | P0 |
| FR-12 | 법령·규정 개정의 영향 조항을 탐색하고 유형·심각도를 판정한다. 서식만 바뀐 경우는 제외한다. | P1 |
| FR-13 | 규정별 담당자 지정. 알림은 앱 내 알림과 메일로 보내고, 하루 1회 묶음 알림과 즉시 알림을 구분한다. | P1 |
| FR-14 | 개정 검토 처리 흐름. 상태와 사유를 기록하고, 새 버전과 자동 연결하며, 기한을 넘기면 다시 알린다. | P1 |
| FR-15 | 시행일 도래 사전 알림 (30일 전, 7일 전) | P1 |
| FR-16 | 검수 화면: 파싱, 시행일, 참조, 충돌 작업을 원문 대조 화면에서 승인·수정한다. | P0 |
| FR-17 | 관리 화면: 대상 기관, 담당자, 동의어 사전, 수집·게시 현황, 품질 지표 | P1 |
| FR-18 | 질의 로그와 사용자 피드백, 감사로그 | P0 |

## 6. 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-01 | **내부망 운영**: 추론 서버(vLLM)를 포함해 모두 기관 내부에서 동작한다. 외부로 나가는 접근은 수집 구간에만 허용한다. |
| NFR-02 | **AI 없이도 핵심 기능이 동작**: LLM이나 임베딩 서버가 멈춰도 열람, 키워드 검색, 비교, 검수는 가능해야 한다. |
| NFR-03 | **일관성**: 한 번의 답변은 하나의 게시 버전 근거만 쓴다. 검색과 그래프가 갱신된 뒤에 게시한다. |
| NFR-04 | **추적성**: 모든 답변에 대해 다음을 다시 확인할 수 있어야 한다. |
|  | · 어떤 게시 버전과 어떤 모델로 답했는가 |
|  | · 어떤 근거를 썼는가 |
|  | · 어떤 검증 결과가 나왔는가 |
| NFR-05 | **성능 (개발 환경 RTX 4090 기준)**: p95 검색 1초 미만, 답변 10초 미만 |
| NFR-06 | **교체 가능성**: LLM, 임베딩, 리랭커, 인프라 엔드포인트는 설정만으로 바꿀 수 있어야 한다. |
| NFR-07 | **정중한 수집**: 출처별 요청을 직렬로 보내고, 최소 간격을 두고, Retry-After를 따른다. 연속으로 실패하면 정지한다. |
| NFR-08 | **개인정보**: 질의에 들어간 개인식별정보는 마스킹한 뒤 저장한다. |

## 7. 범위

- **포함**: ALIO 공개 내부규정, law.go.kr 법령 (D-07 범위), 위의 FR 항목
- **제외 (이번 범위)**
  - 비공개 규정
  - 스캔본 OCR
  - 기관 자체 규정관리시스템 연계
  - 형식 온톨로지 (OWL 등)
  - 법률 자문

## 8. 성공 지표 (초기 목표)

| 지표 | 목표 |
|---|---|
| 조·항·호 구조 파싱 F1 | ≥ 0.97 |
| 검색 Recall@10 | ≥ 0.90 |
| 답변 인용 정확도 | ≥ 0.90 |
| 답변 결론 정확도 | ≥ 0.85 |
| 숫자 일치율 / 결론·설명 일관성 | 1.00 (검증 단계에서 강제) |
| 답할 수 없는 질문을 "판단불가"로 처리한 비율 | ≥ 0.90 |
| 개정 영향 탐지 재현율 | ≥ 0.95 (과거 개정 사후 검증) |
| 서식 변경만으로 보낸 오탐 알림 | 0건 |
| 공포부터 알림까지 걸린 시간 | ≤ 1일 |
| 사용자 "도움됨" 비율, 담당자 검토 처리 시간 | 기준선 측정 후 설정 |

## 9. 릴리스 계획

| 단계 | 결과물 |
|---|---|
| M1 기반 | 수집기와 원본 보관. 대상 기관 목록 수집 |
| M2 구조화 | **파일럿 4개 기관**(NST, 천문연, KIST, ETRI)의 현행·과거 버전 구조화, 검수 큐 |
| M3 열람 | 규정 뷰어, 원문 대조, 버전 비교, 키워드 검색 (LLM 없음) |
| M4 검색·Q&A | 하이브리드 검색, 근거 기반 질의응답, 1차 평가 |
| M5 그래프·알림 | 영향 분석, 담당자 알림, 검토 처리 흐름, 과거 개정 사후 검증 |
| M6 확대 | 전체 출연연 확대, 운영 지표 화면 |

## 10. 의존성과 위험

- **의존성**
  - 실행 중인 nst-nexus 인프라 (PostgreSQL, OpenSearch, S3, Keycloak, Redis, Mailpit)
  - 추론 서버 (Windows PC RTX 4090 → 운영 시 서버 GPU)
  - law.go.kr OC 키
- **주요 위험**
  - ALIO 게시 지연 → 답변에 게시 기준일을 표시한다.
  - HWP 변환 품질 → 검수 큐로 거른다.
  - 소형 LLM의 판단 오류 → 검증 단계를 두고, 실패하면 근거만 보여준다.
  - 공유 인프라 의존 → 백업과 standalone 프로필을 둔다.
- 상세 내용은 [설계 스펙](superpowers/specs/2026-10-01-regulation-platform-design.md) 14~15절을 참고한다.
